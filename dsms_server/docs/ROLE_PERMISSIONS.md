# DSMS 系统角色与权限文档

> 本文档描述 DSMS 缺陷检测管理系统中的系统角色定义及其权限配置
>
> **版本**: v1
>
> **最后更新**: 2026-05-01

---

## 1. 概述

DSMS 采用基于角色的访问控制（RBAC）模型来管理用户权限。系统预置了 6 个系统角色，每个角色拥有不同的权限集合，遵循最小权限原则设计。

### 1.1 角色设计原则

| 原则 | 说明 |
|------|------|
| 最小权限 | 每个角色只拥有完成其职责所需的最小权限 |
| 职责分离 | 不同业务域由不同角色负责 |
| 层级管理 | 权限从低到高形成层级结构 |
| 特殊角色 | 无权限用户用于刚注册或已离职的人员，无任何系统权限 |

## 3. 角色详细定义

### 3.1 无权限用户

**角色标识**: `no_permission_user`

**角色名称**: 无权限用户

**职责等级**: L0 - 无权限

**职责描述**: 刚注册或离职的用户，无任何系统权限，仅能访问登录相关接口。

**权限配置**:
```
无任何权限
```

**权限说明**:
- 没有任何系统操作权限
- 只能访问登录、注册等认证相关接口
- 用于新注册用户或已离职员工
- 需要管理员手动分配有效角色后才能正常使用系统

**适用场景**:
- 新员工注册账号后（等待分配角色）
- 员工离职后（保留账号但取消权限）
- 试用期员工（限制权限）

**权限数量**: 0 条

| `/api/v1/system-messages/my/read-all` | 更新 |
| `/api/v1/announcements/my` | 只读 |
| `/api/v1/announcements/{announcement_id}` | 只读 |
| `/api/v1/announcements/{announcement_id}/read` | 更新 |
| `/api/v1/sse/connect` | 只读 |
| `/api/v1/devices/*` | 只读 |
| `/api/v1/production-lines/*` | 只读 |
| `/api/v1/users/me` | 只读 |
| `/api/v1/users/{user_id}` | 只读 |
| `/api/v1/departments/*` | 只读 |
| `/api/v1/titles/*` | 只读 |
| `/api/v1/roles/*` | 只读 |
| `/api/v1/common/*` | 只读 |
| `/api/v1/auth/*` | 只读 |
| `/api/v1/defect-types` | 只读 |

**权限说明**:
- 可发送和接收用户消息
- 可查看和标记系统消息为已读
- 可查看和确认公告

- 无法进行任何修改或删除操作

**适用场景**:
- 普通员工日常使用系统
- 查看系统公告和消息
- 与其他员工沟通交流
- 查看设备状态等基础信息
- 查看缺陷类型列表

### 3.3 超级系统管理员

**角色标识**: `super_sys_admin`

**角色名称**: 超级系统管理员

**职责等级**: L1 - 最高

**职责描述**: 拥有系统最高权限，可进行所有操作。通常由技术负责人或 CTO 担任。

**权限配置**:
```

```

**权限说明**:
- 不受任何权限限制
- 可管理系统所有功能
- 可修改其他管理员的权限

**适用场景**:
- 系统初始配置
- 紧急故障处理
- 权限体系调整
- 审计监察

## 6. 自定义角色

除系统预置角色外，管理员还可以创建自定义角色来自定义权限组合。

### 6.1 创建自定义角色的注意事项

1. **系统角色不可修改**: 系统预置的 6 个角色不能被修改或删除
2. **权限粒度**: 自定义角色的权限可以精确到单个 API
3. **继承限制**: 自定义角色不能继承系统角色的权限
4. **无权限用户**: 新注册用户或离职员工会被分配此角色，需要管理员手动分配有效角色

### 6.2 权限格式说明

```typescript
interface Permission {
  api: string;          // API 路径，支持通配符
  accessibility: string; // 访问权限
}
```

**通配符规则**:
- `*` - 匹配所有字符
- 示例: `/api/v1/users/*` 匹配所有用户相关 API

**权限值**:
- `*` - 所有 HTTP 方法
- `GET` - 只读
- `POST` - 创建
- `PUT` - 更新
- `DELETE` - 删除
